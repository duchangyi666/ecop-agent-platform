# 状态机与事务边界

## 1. 状态机

| 对象 | 状态 | 合法转换原则 |
| --- | --- | --- |
| 支付 | `requires_action`、`succeeded`、`failed`、`unknown` | 待用户动作可进入成功或失败；未知状态不能被当作失败重试 |
| 退款 | `requested`、`pending`、`succeeded`、`rejected`、`failed`、`unknown_execution_state` | 申请后进入执行；未知执行状态必须先对账，幂等键重复请求返回原记录 |
| 工单 | `open`、`in_progress`、`pending_customer`、`pending_approval`、`escalated`、`resolved`、`closed`、`reopened`、`cancelled` | 由领域转换函数校验，非法边不写入数据库 |
| 审批 | `pending`、`approved`、`rejected`、`modified`、`expired`、`more_information_required` | 审批动作先校验当前状态，再写动作记录和目标状态 |

## 2. 退款事务

退款申请使用一个 Unit of Work：

1. 使用 `TenantScope` 查询当前租户的支付记录。
2. 按 `(tenant_id, idempotency_key)` 查询已有退款。
3. 校验金额不超过支付金额，且不存在未对账的未知执行状态。
4. 写入退款申请并 flush，让唯一约束在当前事务中生效。
5. 正常退出提交；异常退出回滚。

## 3. 工单和审批事务

工单状态转换、工单事件、审批请求和审批动作必须共享同一 Unit of Work。状态转换函数只负责判断合法边，Repository 负责租户内读取和持久化；事务提交后，事件和审计记录与状态变化同时可见。

审批恢复时先读取租户内审批请求，校验当前状态和操作者权限，再写入审批动作、更新请求状态，并同步更新关联工单状态。任何一步失败都回滚，不能留下只有动作没有状态、或只有状态没有审计的半完成结果。

## 4. 异常与回滚

`UnitOfWork.__aexit__` 在无异常退出时提交，在异常退出时回滚并关闭自有 `AsyncSession`。跨租户查询返回空结果或业务层错误，不允许通过修改输入 ID 绕过租户过滤；平台级查询必须单独建模并记录审计。
