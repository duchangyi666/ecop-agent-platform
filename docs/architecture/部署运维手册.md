# 部署运维手册

## 1. Kubernetes 部署

先准备镜像并推送到企业镜像仓库，替换 `infra/kubernetes/*.yaml` 中的 `registry.example.com/clouddesk/backend:latest` 和 `frontend:latest`。

```bash
kubectl apply -f infra/kubernetes/namespace.yaml
kubectl apply -f infra/kubernetes/configmap.yaml
kubectl apply -f infra/kubernetes/secret.example.yaml
kubectl apply -f infra/kubernetes/backend-deployment.yaml
kubectl apply -f infra/kubernetes/backend-service.yaml
kubectl apply -f infra/kubernetes/frontend-deployment.yaml
kubectl apply -f infra/kubernetes/frontend-service.yaml
kubectl apply -f infra/kubernetes/ingress.yaml
```

生产 Secret 不应直接使用 `secret.example.yaml`，应使用外部 Secret 管理：

```bash
kubectl create secret generic clouddesk-secrets \
  --namespace clouddesk \
  --from-literal=JWT_SECRET="$(openssl rand -hex 32)" \
  --from-literal=DEEPSEEK_API_KEY="<secret>"
```

## 2. 数据库备份与恢复

备份：

```bash
docker exec ecop-postgres pg_dump \
  -U app \
  -d enterprise_customer_operations \
  -F c \
  -f /tmp/clouddesk.dump
docker cp ecop-postgres:/tmp/clouddesk.dump ./clouddesk-$(date +%F).dump
```

恢复：

```bash
docker cp ./clouddesk.dump ecop-postgres:/tmp/clouddesk.dump
docker exec ecop-postgres pg_restore \
  -U app \
  -d enterprise_customer_operations \
  --clean \
  --if-exists \
  /tmp/clouddesk.dump
```

恢复后执行迁移校验：

```bash
python -m alembic upgrade head
python scripts/verify_database.py
```

## 3. 对象存储与 Milvus 备份

- MinIO 使用 `mc mirror` 同步 `ecop_minio_data` 到备份桶。
- Milvus 建议按官方工具备份 collection 或使用独立实例快照。
- 备份清单至少包含 PostgreSQL dump、Milvus 数据、MinIO 对象和 `.env` 密钥副本。

## 4. Secret 与密钥轮换

- `JWT_SECRET` 使用至少 32 字节随机值。
- `DEEPSEEK_API_KEY` 只保存在 Secret 或 Vault，不写入日志、Trace 和代码。
- 轮换 JWT Secret 后旧 Token 会立即失效，需要同步通知客户端重新登录。
- 每周验证备份恢复流程，并保存一次恢复演练记录。

## 5. 故障恢复 Runbook

### PostgreSQL 不可用

1. 检查容器健康状态和日志。
2. 禁止业务写操作，前端显示降级页面。
3. 恢复后执行 `alembic upgrade head` 和 `verify_database.py`。

### Milvus 不可用

1. 保留 PostgreSQL 关键词检索降级。
2. 恢复 Milvus 后重新执行知识摄取或 reindex。

### Redis 不可用

1. Worker/Scheduler 暂停任务消费。
2. PostgreSQL 业务事实不受影响。
3. Redis 恢复后 Worker 从队列继续消费。
