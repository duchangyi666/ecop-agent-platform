# 领域模型与数据库设计

## 1. 设计范围

本项目是独立的企业级客户运营平台，Phase 2 先建立可迁移、可审计、可按租户隔离的数据库基础。数据库使用 PostgreSQL，异步访问使用 SQLAlchemy 2.x 与 asyncpg，迁移由 Alembic 管理。

## 2. 领域表清单

| 领域 | 数据表 | 主要职责 |
| --- | --- | --- |
| 租户与权限 | `tenants`、`users`、`roles`、`permissions`、`user_roles` | 租户、用户、角色和权限关系 |
| 客户与计费 | `customers`、`customer_contacts`、`subscriptions`、`invoices`、`payments`、`refunds` | 客户主数据、订阅、账单、支付和退款幂等 |
| 工单与审批 | `tickets`、`ticket_messages`、`ticket_events`、`ticket_assignments`、`approval_requests`、`approval_actions`、`audit_logs` | 工单生命周期、事件、分配、人工审批和审计 |
| 知识与策略 | `documents`、`document_versions`、`knowledge_chunks`、`policies`、`policy_versions`、`memory_records` | 知识文档、分片、策略版本和带 TTL 的记忆候选 |
| Agent 与模型 | `agent_definitions`、`agent_versions`、`prompt_definitions`、`prompt_versions`、`model_profiles`、`feature_flags` | Agent、Prompt、模型配置和特性开关 |
| 运行与评测 | `runtime_traces`、`runtime_spans`、`tool_executions`、`evaluation_datasets`、`evaluation_cases`、`evaluation_runs`、`evaluation_results` | Agent 运行轨迹、工具执行和离线评测 |

## 3. 公共字段和租户隔离

除根租户表 `tenants` 外，业务表统一包含 `tenant_id`、`created_at`、`updated_at` 和可空 `deleted_at`。Repository 查询必须同时添加当前租户条件和 `deleted_at IS NULL`，平台级审计查询必须使用显式平台接口，不能通过普通租户 Repository 绕过过滤。

关键跨表关系使用包含 `tenant_id` 的复合外键，例如支付与发票、退款与支付、用户角色与角色，保证同一个业务对象不能跨租户拼接。

## 4. 金额、幂等和审计

- 金额字段统一使用 `NUMERIC(18, 2)`，应用层使用 `Decimal`，避免浮点误差。
- 支付外部编号使用租户内唯一约束；退款使用 `(tenant_id, idempotency_key)` 唯一约束。
- 退款申请在同一事务内完成租户内支付检查、幂等查询和新增；未知执行状态必须先经过对账。
- 审批请求、审批动作和工单事件保存状态变化摘要与操作者边界；敏感 payload 在落库前脱敏，原始 Prompt 不写入运行轨迹。

## 5. 迁移链

迁移按 `001_identity_tables`、`002`、`003`、`004`、`005`、`006` 顺序建立身份、计费、工单治理、Agent 运行评测、退款审批和知识分片表。验收脚本会检查完整表集合、租户字段、金额精度、关键唯一约束和当前 Alembic 版本。
