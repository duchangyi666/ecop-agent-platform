# 模型网关与结构化回复安全实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** 基于当前实际环境，为客服 Agent 增加可注入的 DeepSeek 模型网关、Pydantic 结构化回复、安全输出过滤和 LangGraph 客服子图接入，同时保证测试不依赖真实 API Key 或外网。

**Architecture:** 以 \`ModelGateway\` Protocol 隔离模型供应商；\`DeepSeekGateway\` 通过当前已安装的 HTTPX 访问 OpenAI-compatible Chat Completions，\`FakeModelGateway\` 提供离线测试响应。客服子图顺序固定为 \`build_response_context -> customer_service_model -> response_safety_filter\`，模型只生成回复草稿，不能执行数据库、退款、审批或工单工具。

**Tech Stack:** Python 3.11.15、HTTPX 0.28.1、Pydantic 2.11.4、langchain-core 1.2.16、LangGraph 1.0.9、FastAPI 0.117.1、pytest 8.3.4、pytest-asyncio 0.24.0。

## 全局约束

- 当前分支继续使用 \`E:\\anaconda3\\envs\\edu_agent\\python.exe\`，并设置 \`PYTHONNOUSERSITE=1\`。
- \`DEEPSEEK_API_KEY\` 只允许从运行时环境变量读取；不得写入仓库、测试数据、命令行参数、日志、异常消息或文档。
- 不使用用户在对话中暴露的旧 Key；真实冒烟测试必须由用户撤销旧 Key、生成新 Key 并在本机设置环境变量后单独执行。
- 不引入 \`openai\` 或其他未核验 SDK；使用当前已安装且已核验的 \`httpx==0.28.1\`，直接调用 OpenAI-compatible HTTP 接口。
- \`langchain-core==1.2.16\` 作为直接依赖声明，用于客服 Prompt 构造；模型供应商调用仍通过 ModelGateway 隔离。
- 模型调用失败不进入退款业务重试；结构化输出失败、敏感输出和未经证据支持的业务承诺均不能触发业务工具。
- 现有 Input Security Guard、Domain Guard、RBAC、退款策略、审批恢复和工具白名单继续位于模型调用之前或之外。
- 所有新增文档使用中文文件名；真实 API 测试默认不纳入自动测试套件。

### Step 2: 实现 HTTP Gateway

- 使用 \`httpx.AsyncClient.post("/chat/completions")\`；
- 请求头只在内存中生成 \`Authorization: Bearer <SecretStr>\`，不得进入日志；
- 请求体使用 \`model\`、system/user messages、\`response_format={"type":"json_object"}\`、\`temperature=0\`、\`stream=False\`；
- System Prompt 中明确要求输出 \`ResponseDraft.model_json_schema()\` 对应的 JSON 字段；
- 从 \`choices[0].message.content\` 解析 JSON，再调用 \`response_model.model_validate\`；
- 使用 \`time.perf_counter()\` 计算 latency_ms，只返回 token 数和供应商元数据；
- 仅对 \`httpx.TimeoutException\`、\`httpx.TransportError\` 和 HTTP 5xx 执行配置次数的有限重试；
- HTTP 4xx、JSON 错误、结构化校验错误不重试；
- 所有对外错误转换为 \`ModelGatewayError\`，safe_message 不包含供应商原文、Key、Prompt 或响应。
