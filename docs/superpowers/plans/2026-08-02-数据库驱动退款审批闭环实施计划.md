# 数据库驱动退款审批闭环实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在当前独立项目中实现数据库驱动的退款申请、风险审批、审计追踪和可恢复 Checkpoint 闭环。

**Architecture:** 保留现有 LangGraph Supervisor + 五个专属 Agent 结构，由 `RefundWorkflowService` 作为应用服务控制数据库事务。Agent 只输出结构化意图，Unit of Work 负责租户作用域查询、退款申请、审批请求、审计和运行追踪。Checkpoint 使用 PostgreSQL 持久化，内存实现继续用于纯单元测试。

**Tech Stack:** Python 3.11.15、LangGraph 1.1.10、SQLAlchemy 2.0.49、asyncpg 0.30.0、Pydantic 2.12.5、Alembic 1.18.5、PostgreSQL 15、pytest 8.3.4、pytest-asyncio 0.24.0。

## Global Constraints

- 所有工作只在 `E:\ai\enterprise-customer-operations-platform\.worktrees\phase-2-domain-database` 分支工作树中进行，不创建子 Agent，不修改现有项目。
- 使用 `E:\anaconda3\envs\edu_agent\python.exe`，并设置 `$env:PYTHONNOUSERSITE = "1"`。
- PostgreSQL 使用项目专用容器端口 `54329`，禁止使用 `docker compose down -v`。
- 所有业务查询和写入必须带 `TenantScope`；跨租户资源统一表现为“不可见”。
- 金额使用 `Decimal`；退款幂等键按租户隔离；未知执行状态禁止自动重试。
- 每项生产代码先写一个能证明缺口的失败测试，再实现最小代码使其通过。
- 不接入外部支付平台 SDK；“完成”只表示本地退款申请或审批状态已持久化，不表示第三方资金已经到账。
- 新增说明文档使用中文文件名；`README.md`、`pyproject.toml` 和 Python 文件名遵循生态约定。
