# 领域模型与数据库实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 CloudDesk 客服 Agent 平台建立可迁移、可测试、带租户隔离和业务约束的 PostgreSQL 领域模型、SQLAlchemy 2.x 模型、Alembic 迁移和 Repository 接口，支撑第一条“重复扣费与退款”闭环。

**Architecture:** 采用领域模型、应用服务、数据库模型和 Repository 分层。PostgreSQL 是业务事实来源；金额使用 `Decimal`，时间统一使用 UTC，所有租户业务表包含 `tenant_id`。第一阶段先实现租户与权限、客户与账单、工单与审批、知识与运行时治理四组表，并通过异步数据库会话和租户作用域 Repository 对外提供访问。

**Tech Stack:** Python 3.11、SQLAlchemy 2.0.36、asyncpg 0.30.0、Pydantic 2.11.4、Alembic、PostgreSQL 15、pytest 8.3.4、pytest-asyncio 0.24.0。

## Global Constraints

- 项目根目录固定为 `E:\ai\enterprise-customer-operations-platform`。
- 不导入、不复制、不依赖 `E:\ai\EduAgent完整代码` 中的业务模块、数据库或配置。
- 后端 Python 使用 3.11；SQLAlchemy 使用 2.0.36；asyncpg 使用 0.30.0；Pydantic 使用 2.11.4。
- 金额字段使用 PostgreSQL `NUMERIC(18, 2)` 和 Python `Decimal`，禁止使用 `float` 保存金额。
- 时间字段使用带时区的 UTC 时间；应用层统一生成 UTC 时间。
- 所有租户业务表包含 `tenant_id`；Repository 必须自动添加租户条件，调用方不能绕过该条件。
- 关键表使用软删除字段和审计字段；支付、退款和审批使用数据库唯一约束。
- 退款操作使用幂等键；未知执行状态不能通过普通重试再次执行。
- 工单、审批和退款状态通过显式状态机转换，禁止任意字符串更新状态。
- SQLAlchemy 查询使用 2.x `select()` 风格和异步 `AsyncSession`。
- 文档文件使用中文命名；源码文件名采用稳定的 Python/TypeScript 模块命名，不以中文文件名替代源码模块。
- 每个任务先写失败测试，再实现最小代码，再运行定向测试，最后提交独立 commit。
- 本计划只覆盖 Phase 2；RAG、Agent 图、模型路由、前端和部署作为独立计划处理。
