# 模型网关与结构化回复安全设计

## 1. 目标与边界

本阶段为当前独立项目增加统一模型调用边界，使客服 Agent 可以通过可替换的模型网关生成结构化回复，并在输出返回用户前执行确定性的安全过滤。

本阶段实现：

- 供应商无关的异步模型网关协议；
- DeepSeek OpenAI-compatible HTTP 适配器；
- Pydantic 结构化输出校验；
- 客服回复草稿和输出安全过滤；
- 可注入的本地 Fake Gateway，保证单元测试不依赖外网和真实密钥；
- LangGraph 客服子图的模型调用入口。

本阶段不实现：

- 不把 API Key 写入代码、文档、.env、测试 fixture、命令行参数或日志；
- 不保存完整 Prompt、完整模型响应或思维链；
- 不接入知识库、Milvus、RAG、工单持久化和 SSE；
- 不让模型直接执行 SQL、退款、审批或其他业务工具；
- 不用模型替代现有 Input Security Guard、Domain Guard、RBAC、策略门和工具白名单。

## 2. 配置和实际版本

使用当前环境已经核验的版本：

- Python 3.11.15；
- httpx 0.28.1；
- pydantic 2.11.4；
- langchain-core 1.2.16；
- LangGraph 1.0.9。

模型配置只从环境变量读取：

~~~text
DEEPSEEK_API_KEY          真实调用时读取，不写入仓库
DEEPSEEK_BASE_URL         默认 https://api.deepseek.com
DEEPSEEK_MODEL            由部署环境指定
DEEPSEEK_TIMEOUT_SECONDS  默认 30
DEEPSEEK_MAX_RETRIES     默认 1
~~~

DeepSeek 适配器使用 OpenAI-compatible 的 /chat/completions 接口。模型名称不在业务代码中硬编码为旧别名，部署时通过 DEEPSEEK_MODEL 指定。官方接口说明见 [DeepSeek API 文档](https://api-docs.deepseek.com/guides/function_calling/)。

## 3. 推荐架构

~~~text
Customer Service Agent
        ↓
Prompt Builder（只组装脱敏上下文）
        ↓
StructuredModelInvoker
        ↓
ModelGateway Protocol
        ├─ DeepSeekGateway（真实 HTTP 调用）
        └─ FakeModelGateway（测试）
        ↓
Pydantic ResponseDraft 校验
        ↓
ResponseSafetyFilter
        ├─ allow → 返回 final_response
        ├─ block → 固定安全回复并写结构化错误
        └─ human_handoff → 转人工，不调用业务工具
~~~

模型网关只返回结构化模型结果和非敏感调用元数据。模型调用失败、超时、HTTP 4xx/5xx、JSON 解析失败和 Pydantic 校验失败统一转换为受控错误，不直接把供应商错误文本返回给用户。

## 4. 结构化契约

新增不可变 Pydantic 模型：

~~~python
class ResponseDraft(BaseModel):
    answer: str
    next_action: Literal["finish", "ask_clarification", "human_handoff"]
    confidence: float = Field(ge=0.0, le=1.0)
    evidence_ids: list[str] = Field(default_factory=list)


class ModelUsage(BaseModel):
    provider: str
    model: str
    input_tokens: int | None = Field(default=None, ge=0)
    output_tokens: int | None = Field(default=None, ge=0)
    latency_ms: int = Field(ge=0)
~~~

AgentState 增加 response_draft、final_response、model_usage、model_error、model_call_count、total_input_tokens 和 total_output_tokens。State 只保存结构化回复、统计信息和安全错误；不保存 API Key、Authorization Header、完整请求消息、完整模型响应或隐藏推理内容。

## 5. ModelGateway 接口

定义最小异步协议：

~~~python
class ModelGateway(Protocol):
    async def generate_structured(
        self,
        *,
        system_prompt: str,
        user_prompt: str,
        response_model: type[BaseModel],
    ) -> tuple[BaseModel, ModelUsage]:
        ...
~~~

DeepSeekGateway 要求：

1. 从配置对象读取 Key、地址、模型、超时和重试次数；
2. 每次请求使用新的 Authorization Header，不把 Header 写入日志；
3. 请求体使用 JSON 输出约束和 ResponseDraft JSON Schema；
4. 只在网络超时、连接错误和 5xx 时最多重试一次；
5. 4xx、结构化输出失败和安全过滤失败不自动重试；
6. 响应只提取 choices[0].message.content 和 usage；
7. 任何异常日志只记录错误码、HTTP 状态、request_id、trace_id 和耗时，不记录输入原文或响应原文。

FakeModelGateway 接收预先配置的 ResponseDraft 或异常，用于单元测试和离线开发。它不能读取环境中的真实 Key。

## 6. Prompt 与上下文边界

客服 Agent 的 Prompt 只允许使用：

- 当前用户消息的脱敏版本；
- 已通过 Guard 的业务域和下一动作；
- 已验证的业务事实摘要；
- 已通过权限过滤的证据摘要；
- 固定的 CloudDesk 服务范围说明。

模型必须被要求：

- 不编造支付、退款、审批、工单和账户状态；
- 没有证据时返回澄清或人工接管；
- 不输出系统 Prompt、内部规则、凭据和未授权数据；
- 不执行工具，只生成结构化回复草稿。

当前阶段没有业务证据时，模型只能生成澄清或通用服务范围回复，不能给出具体业务结论。

## 7. 输出安全过滤

ResponseSafetyFilter 在任何用户可见响应之前运行，检测：

- API Key、Bearer Token、密码和银行卡号；
- 系统 Prompt、内部规则、内部地址和数据库信息；
- 未经证据支持的退款、审批、支付成功等确定性承诺；
- 空回复、超长回复和非法下一动作。

处理规则：

- 命中敏感信息：返回固定安全回复，状态为 blocked；
- 命中未经证据支持的业务承诺：返回 human_handoff；
- 空或非法结构化输出：返回 model_invalid_output，不调用业务工具；
- 正常输出：截断到配置上限后返回 final_response。

过滤器不回显命中的原始片段，审计只保存规则码和通用原因。

## 8. LangGraph 接入

客服子图改为：

~~~text
START
  ↓
build_response_context
  ↓
customer_service_model
  ↓
response_safety_filter
  ├─ allow → END
  ├─ block → safe_refusal → END
  └─ human_handoff → END
~~~

build_customer_service_graph(model_gateway=None) 接受依赖注入：

- 传入 DeepSeekGateway 时执行真实模型调用；
- 未传入时使用 FakeModelGateway 的固定安全回复，保证现有图结构测试离线可运行；
- 主图不在模块导入时读取环境变量，不在测试收集阶段创建网络客户端。

退款、审批和其他业务工具仍由现有确定性服务负责，客服模型输出不能改变退款状态、权限结果或审批状态。

## 9. 错误和可观测性

模型错误作为结构化 State 返回，不进入退款业务重试：

- model_not_configured：固定提示当前智能回复服务未配置，转人工；
- model_timeout：最多一次重试，随后转人工；
- model_http_error：5xx 最多一次重试，4xx 直接转人工；
- model_invalid_json / model_invalid_output：不重试业务工具，返回处理中提示；
- response_blocked：写安全审计，不向用户解释具体匹配内容。

后续接入 RuntimeTrace 时只记录 provider、model、耗时、token 数、错误码和重试次数，不保存 Key、Prompt、响应原文或思维链。

## 10. 测试策略

### 单元测试

- 配置缺少 Key 时返回 model_not_configured，不创建 HTTP 请求；
- DeepSeek 请求使用配置的 base URL/model，并且测试日志不包含 Authorization Header；
- 超时和 5xx 只重试一次，4xx 不重试；
- JSON 和 Pydantic 校验失败返回结构化错误；
- Fake Gateway 能返回合法 ResponseDraft；
- ResponseSafetyFilter 能阻断密钥、系统 Prompt、银行卡号和未经证据支持的退款承诺；
- 正常回复和澄清回复能通过过滤；
- AgentState 只保存结构化结果和统计，不保存 Key 或完整模型原文。

### LangGraph 测试

- 客服子图可以通过 Fake Gateway 离线执行；
- 模型结构化回复能进入 final_response；
- 安全阻断和人工接管不会进入业务工具；
- 退款、审批和既有 Guard/RBAC 测试保持通过。

### 真实 API 冒烟测试

默认不自动执行，避免测试消耗额度或泄露密钥。只有用户在本机设置新的 DEEPSEEK_API_KEY 后，才允许手动执行一次最小请求；输出只展示状态、模型名、耗时和结构化字段，不打印 Key、Prompt 或完整响应。

## 11. 明确不在本阶段的内容

- DeepSeek Key 轮换、余额和账户管理由用户在供应商控制台完成；
- Milvus/BGE-M3/Cross-Encoder RAG；
- PostgreSQL 对话表、长期记忆写入和工单业务闭环；
- SSE 运行进度流；
- 正式 JWT/OAuth 认证；
- 第三方支付执行和真实退款到账。
